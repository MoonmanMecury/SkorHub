## 2025-05-14 - Lenco Webhook Authentication Bypass and Timing Attack
**Vulnerability:** The Lenco webhook implementation was prone to fail-open logic where missing signature headers or environment variables would bypass authentication, and used insecure string comparisons (`!==`) vulnerable to timing attacks. Additionally, JSON parsing was performed before authentication, presenting a DoS risk.
**Learning:** Webhook handlers must implement fail-secure logic by explicitly rejecting requests when expected security parameters (like hash keys or signature headers) are absent. Utilizing constant-time comparison functions like `crypto.timingSafeEqual` is critical for preventing side-channel attacks on cryptographic signatures.
**Prevention:** Always validate the presence of security-critical configuration and headers first. Use `crypto.timingSafeEqual` for all signature verifications. Defer resource-intensive operations like JSON parsing until after the request has been authenticated.
